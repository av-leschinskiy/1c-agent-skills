# Инструменты агента для разработки на 1С

Скиллы и MCP-сервер для AI-агентов (Codex, Claude Code, Cursor и других):

| Что | Зачем |
| --- | --- |
| [testing-with-yaxunit](skills/testing-with-yaxunit/SKILL.md) | скилл: подключить YAxUnit, писать юнит- и интеграционные тесты в расширении тестов, запускать и читать jUnit |
| [testing-with-vanessa](skills/testing-with-vanessa/SKILL.md) | скилл: писать сценарии Vanessa Automation по живым формам через MCP Vanessa, запускать пакетно, читать JUnit, статус и Allure |
| [mcp/objects](mcp/objects) и [extensions/СервисОбъектов](extensions/СервисОбъектов) | MCP-сервер `onec-objects`: агент ищет типы и объекты, читает схему и объект, создаёт элемент справочника или непроведённый документ в вашей базе. Работает через HTTP-сервис расширения `СервисОбъектов` |

Знания собраны на курсе «Разработка на 1С с AI-агентами» (Infostart, 2026): занятия
о MCP-сервере над 1С, YAxUnit и TDD, сценарном тестировании с Vanessa Automation,
прогоны и разбор домашних работ.

Ничего не привязано к машине и к харнессу. Пути, базы, порты и учётная запись — в разделе
«Окружение 1С» в `AGENTS.md` вашего проекта и в записи MCP вашего харнесса; агент
заполняет их вместе с вами.

## Как подключить

Скажите своему агенту:

> Подключи скиллы и MCP из https://github.com/av-leschinskiy/1c-agent-skills по инструкции
> в его README.

Обновить — так же:

> Обнови инструменты из 1c-agent-skills по его README.

## Инструкция для агента

Этот репозиторий подключается **клоном git** и обновляется **`git pull`**. Механизмы
плагинов и маркетплейсов харнессов (`/plugin`, `codex plugin`, каталоги Cursor),
`skill-installer`, npm-пакеты и копирование файлов не использовать: копия не обновляется,
а плагин у каждого харнесса свой. Клон один, харнесс читает его через ссылки и запись MCP.

Ты работаешь в каком-то харнессе — подключай для него и спроси человека, нужны ли другие
харнессы на этой машине. Формат своего MCP-конфига и каталог своих скиллов ты знаешь
или находишь в документации харнесса; ниже — что туда записать.

### 1. Клон

Спросить человека, где подключать:

- **для всех проектов** (по умолчанию) — клон в `~/.agents/vendor/1c-agent-skills`;
- **в проект** — подмодуль `vendor/1c-agent-skills`: версия фиксируется коммитом
  проекта, коллеги получают её вместе с репозиторием.

```bash
git clone https://github.com/av-leschinskiy/1c-agent-skills.git ~/.agents/vendor/1c-agent-skills
# или в проекте:
git submodule add https://github.com/av-leschinskiy/1c-agent-skills.git vendor/1c-agent-skills
```

Дальше `<клон>` — абсолютный путь к нему.

### 2. Скиллы

Для каждого каталога `<клон>/skills/<имя>` создать ссылку `<имя>` в каталоге скиллов
своего харнесса — пользовательском при клоне для всех проектов, проектном при подмодуле.
Известные каталоги:

| Харнесс | Для всех проектов | В проекте |
| --- | --- | --- |
| Codex, Cursor и другие, читающие `.agents/skills` | `~/.agents/skills` | `.agents/skills` |
| Claude Code | `~/.claude/skills` | `.claude/skills` |

Ссылка на каталог: Linux и macOS — `ln -s <клон>/skills/<имя> <каталог скиллов>/<имя>`;
Windows — `New-Item -ItemType Junction -Path <каталог скиллов>\<имя> -Target <клон>\skills\<имя>`
(junction не требует прав администратора). Существующий каталог с тем же именем не
перезаписывать — показать человеку и спросить.

### 3. MCP-сервер `onec-objects`

Нужны Node.js 22+, база 1С с HTTP-публикацией (Apache или IIS) и права загрузить в неё
расширение. Если человек не хочет давать агенту запись в базу — этот шаг пропустить.

1. Собрать сервер:

   ```bash
   cd <клон>/mcp/objects && npm ci && npm run build
   ```

2. Загрузить в базу расширение из `<клон>/extensions/СервисОбъектов` (XML, формат 8.3.24,
   режим совместимости 8.3.24) — Конфигуратором «Конфигурация → Расширения конфигурации →
   Загрузить из файлов» или командой
   `1cv8 DESIGNER /F"<база>" /N"<пользователь>" /LoadConfigFromFiles "<клон>/extensions/СервисОбъектов" -Extension СервисОбъектов /UpdateDBCfg -Extension СервисОбъектов`.
   Закрыть перед этим сеансы 1С базы. Опубликовать HTTP-сервисы расширения
   («Администрирование → Публикация на веб-сервере», флажок HTTP-сервисов).
3. Проверить сервис: `GET <адрес публикации>/hs/objects/types?q=.&limit=5` с Basic-авторизацией
   пользователя 1С отвечает JSON с `items`. 401 — неверный пользователь, 404 — не
   опубликованы HTTP-сервисы или расширение не загружено.
4. Добавить в MCP-конфиг харнесса stdio-сервер:

   | Поле | Значение |
   | --- | --- |
   | имя | `onec-objects` |
   | команда | `node` |
   | аргументы | `<клон>/mcp/objects/dist/index.js` (абсолютный путь) |
   | окружение | `ONEC_HTTP_URL` — адрес публикации без `/` в конце; `ONEC_USER` — пользователь 1С; `ONEC_PASSWORD` — пароль, если есть |

   Пароль — только в пользовательском конфиге харнесса или в переменной окружения
   системы, не в файле проекта под git. Для подмодуля в проекте запись с адресом и
   пользователем можно положить в проектный конфиг, а пароль — нет.
5. Проверить в новой сессии: инструмент `find_types` с запросом `.` возвращает типы базы.

Сервер Vanessa в этот шаг не входит: его запускает менеджер тестирования, запись
описана в скилле `testing-with-vanessa`.

### 4. Итог

Новая сессия агента видит скиллы и инструменты `onec-objects`. Сказать человеку, что при
первом использовании скилл попросит заполнить «Окружение 1С» в `AGENTS.md` проекта.

### Обновить

1. Запомнить ревизию и обновить:

   ```bash
   git -C <клон> rev-parse HEAD
   git -C <клон> pull --ff-only
   git -C <клон> diff --stat <прежняя ревизия> HEAD
   ```

2. По списку изменённых файлов:
   - `skills/` — ничего не делать: ссылки смотрят в клон. Новый каталог скилла — добавить
     ссылку (шаг 2);
   - `mcp/objects/` — пересобрать (`npm ci && npm run build`) и перезапустить сессию;
   - `extensions/СервисОбъектов/` — загрузить расширение в базу заново (шаг 3.2).
3. Для подмодуля — закоммитить в проекте новую ревизию подмодуля.
4. Рассказать человеку, что изменилось, по `git -C <клон> log --oneline <прежняя ревизия>..HEAD`.

`pull` отказал из-за локальных правок — в клоне что-то правили. Не сбрасывать: показать
человеку `git -C <клон> diff`. Значения машины переносятся в `AGENTS.md` проекта
или запись MCP, исправление предлагается в этот репозиторий (issue или pull request),
затем `git -C <клон> checkout -- .` и снова `pull`.

### Не делать

- Не править файлы в клоне: всё, что зависит от машины, — в `AGENTS.md` проекта и записи MCP.
- Не класть пароли и токены в `AGENTS.md`, проектные конфиги и коммиты.
- Не ставить эти скиллы плагином или из маркетплейса параллельно с клоном: два источника
  одного скилла расходятся.

## Почему git, а не плагин

Плагин и маркетплейс — тот же git-репозиторий плюс манифест, каталог, версия и кэш у
каждого харнесса в своём формате. Для набора скиллов и одного MCP-сервера это лишние
движущиеся части: `SKILL.md` читают все харнессы, запись MCP умеет каждый, а git уже даёт
версии, историю, ревью и обновление.

## Проверено

- Скиллы — на прогонах курса (Linux, платформа 8.5, Codex и Claude Code).
- MCP-сервер — тестами (`npm test`) и на курсе в составе расширения учебного проекта.
- Расширение `СервисОбъектов` выделено из него для этого репозитория; XML проходит
  статическую проверку. Загрузку на 8.3.24–8.3.27 подтвердите на своей базе и сообщите,
  если что-то не так.
