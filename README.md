# Скиллы агента для тестирования 1С

Скиллы для AI-агентов (Codex, Claude Code, Cursor и других), которые пишут и запускают
тесты 1С:

| Скилл | Что делает |
| --- | --- |
| [testing-with-yaxunit](skills/testing-with-yaxunit/SKILL.md) | подключает YAxUnit, пишет юнит- и интеграционные тесты в расширении тестов, запускает и читает jUnit |
| [testing-with-vanessa](skills/testing-with-vanessa/SKILL.md) | пишет сценарии Vanessa Automation по живым формам через MCP, запускает пакетно, читает JUnit, статус и Allure |

Знания собраны на курсе «Разработка на 1С с AI-агентами» (Infostart, 2026): занятия
о YAxUnit и TDD и о сценарном тестировании с Vanessa Automation, прогоны и разбор
домашних работ.

Скиллы не привязаны к машине. Пути, базы, порты и профиль клиента агент берёт из раздела
«Окружение 1С» в `AGENTS.md` вашего проекта и при первом использовании заполняет его
вместе с вами.

## Как подключить

Попросите своего агента:

> Подключи скиллы из https://github.com/av-leschinskiy/1c-agent-skills по инструкции
> в его README.

Агент выполнит раздел ниже.

## Инструкция для агента

Этот репозиторий подключается **клоном git** и обновляется **`git pull`**. Механизмы
плагинов и маркетплейсов харнессов (`/plugin`, `codex plugin`, каталоги Cursor),
`skill-installer` и копирование файлов не использовать: копия не обновляется, а плагин
у каждого харнесса свой. Клон один, харнессы читают его через ссылки.

### Подключить

1. Спросить человека, где подключать:
   - **для всех проектов** (по умолчанию) — клон в `~/.agents/vendor/1c-agent-skills`,
     ссылки в пользовательские каталоги скиллов;
   - **в проект** — подмодуль git `vendor/1c-agent-skills`, ссылки в каталоги скиллов
     проекта. Тогда версия скиллов фиксируется коммитом проекта, и коллеги получают её
     вместе с репозиторием.
2. Клонировать:
   - для всех проектов: `git clone https://github.com/av-leschinskiy/1c-agent-skills.git ~/.agents/vendor/1c-agent-skills`
   - в проект: `git submodule add https://github.com/av-leschinskiy/1c-agent-skills.git vendor/1c-agent-skills`
3. Для каждого каталога `skills/<имя>` клона создать ссылку на каталог `<имя>` в каталогах
   скиллов харнессов человека:

   | Харнесс | Для всех проектов | В проекте |
   | --- | --- | --- |
   | Codex, Cursor | `~/.agents/skills/<имя>` | `.agents/skills/<имя>` |
   | Claude Code | `~/.claude/skills/<имя>` | `.claude/skills/<имя>` |

   Cursor читает также `.claude/skills`, поэтому для него хватает любой из строк.
   Ссылка на каталог: Linux и macOS — `ln -s <клон>/skills/<имя> <каталог скиллов>/<имя>`;
   Windows — `New-Item -ItemType Junction -Path <каталог скиллов>\<имя> -Target <клон>\skills\<имя>`
   (junction не требует прав администратора). Существующий каталог с тем же именем не
   перезаписывать — показать человеку и спросить.
4. Проверить: новая сессия агента видит скиллы `testing-with-yaxunit`
   и `testing-with-vanessa`.
5. Сказать человеку, что при первом использовании скилл попросит заполнить «Окружение 1С»
   в `AGENTS.md` проекта.

### Обновить

```bash
git -C <клон> pull --ff-only
```

Для подмодуля — та же команда в `vendor/1c-agent-skills`, затем коммит проекта
с новой ревизией подмодуля. Ссылки обновлять не нужно. Новый скилл в репозитории —
добавить на него ссылку, как в шаге 3.

`pull` отказал из-за локальных правок — в клоне правили скилл. Не сбрасывать: показать
человеку `git -C <клон> diff`. Значения машины переносятся в `AGENTS.md` проекта,
исправление скилла предлагается в этот репозиторий (issue или pull request), затем
`git -C <клон> checkout -- .` и снова `pull`.

### Не делать

- Не править файлы в клоне: всё, что зависит от машины, — в `AGENTS.md` проекта.
- Не класть в `AGENTS.md`, конфиги и коммиты пароли и токены.
- Не ставить эти скиллы плагином или из маркетплейса параллельно с клоном: два источника
  одного скилла расходятся.

## Почему git, а не плагин

Плагин и маркетплейс — тот же git-репозиторий плюс манифест, каталог, версия и кэш у
каждого харнесса в своём формате. Для набора скиллов это лишние движущиеся части:
`SKILL.md` читают все харнессы, а git уже даёт версии, историю, ревью и обновление.
