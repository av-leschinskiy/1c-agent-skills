# Сценарии Vanessa Automation

Значения машины — платформа, рабочая база, база-менеджер, профиль клиента, порт MCP,
каталог отчётов — лежат в `AGENTS.md` проекта, раздел «Окружение 1С». Раздела нет —
заполнить вместе с человеком по [references/environment.md](references/environment.md);
там же запуск менеджера, запись MCP и пакетный прогон. Как раскладывать и называть
сценарии — [references/scenarios.md](references/scenarios.md).

## Как это устроено

Две 1С. Менеджер тестирования — отдельная пустая база с обработкой Vanessa и MCP-сервером
внутри. Клиент тестирования — рабочая база, запущенная с `/TESTCLIENT`: менеджер нажимает
в ней кнопки и читает поля по протоколу режима тестирования платформы, как пользователь.
Рабочая база о тесте не знает.

Два способа работы, у каждого своя задача:

- **MCP** — агент исследует живую форму: имена элементов, реакция на ввод, разбор
  упавшего шага. Нужен, пока сценарий пишется.
- **Пакетный запуск** — готовый сценарий без агента и без MCP: Vanessa сама поднимает
  менеджер и клиент, прогоняет шаги и пишет отчёты. Так сценарий гоняют в MR и ночью,
  так же принимается результат.

Агент подключает MCP-серверы при старте сессии. Менеджер, поднятый позже, сессия не
увидит — нужна новая сессия. Перед выводом «инструментов нет» различать: сервер
показан подключённым, инструмент реально вызывается, проверка выполнена.

## Порядок работы

1. Нет инструментов `vanessa` в сессии — сказать человеку и остановиться. К серверу
   по HTTP самому не обращаться.
2. `manage_test_client` с действием `connect` и профилем из «Окружения 1С».
3. Начинать с образца в каталоге сценариев проекта, а не с исследования формы. Образца
   нет — первым делом записать путь «открыть раздел, создать, заполнить, записать».
4. Сначала шаги в feature, затем `open_feature_file`, `check_syntax`, `run_scenario`
   с `reloadAndRun`: оба работают с файлом, открытым в редакторе Vanessa. Упавший шаг
   разбирать по форме (`get_form_analysis` с `only_visible` и `compact`,
   `get_form_element_data`). Ручные действия в форме — только чтобы узнать имя элемента,
   не вместо сценария.
5. Пути файлов в инструментах `vanessa` — полные, как их видит 1С.
6. Пробный сценарий для одного шага — в каталоге логов, не в каталоге сценариев.
7. Готово — только свежий пакетный прогон: `status.txt` со значением 0, JUnit без
   failures и errors, непустой отчёт. Success через MCP — ещё не готово.

## Red или сломанный тест

Red — сценарий упал на проверке требования: «поле Скидка имеет значение 0,00, а ожидалось
50,00», или нет колонки, которую требует задача. Тогда пишется код.

Не Red, а сломанный тест — окно не найдено, элемент не тот, данные не подготовлены,
сценарий не загрузился, клиент не подключён, ожидание записано неверно (например,
обычный пробел вместо неразрывного в разделителе тысяч). Такой сценарий чинить.

Ожидаемое значение — из требования. Форма показывает другое — это находка: сообщить
человеку, а не подгонять ожидание. Green — тот же сценарий с тем же ожиданием.

## Шаги, которые работают

Имя шага не искать `search_for_steps_by_keywords`, если оно есть здесь или в образце.

| Нужно | Шаг |
|---|---|
| Подключиться к клиенту | в `Контекст`: `Дано я подключаю профиль TestClient "<профиль>"` — без него пакетный прогон берёт клиент менеджера |
| Чистое начало | в `Контекст`: `И я закрываю все окна клиентского приложения` |
| Открыть раздел | `И В командном интерфейсе я выбираю '<Раздел>' '<Команда>'`, затем `Тогда открылось окно '<Заголовок>'` |
| Открыть список по ссылке | `Когда я перехожу по навигационной ссылке 'e1cib/list/Документ.<Имя>'` |
| Уникальное значение | `И Я запоминаю значение выражения 'Формат(ТекущаяУниверсальнаяДатаВМиллисекундах(), "ЧГ=0")' в переменную "Метка"`, дальше `'$Метка$'` |
| Поле ввода | `И в поле с именем '<Имя>' я ввожу текст '<текст>'` |
| Ссылочное поле шапки | `И из выпадающего списка с именем '<Имя>' я выбираю по строке '<текст>'` |
| Ссылочная колонка таблицы | `И в таблице "<Таблица>" из выпадающего списка с именем '<Колонка>' я выбираю по строке '<текст>'` |
| Ввод в ячейку | `И в таблице "<Таблица>" в поле с именем '<Колонка>' я ввожу текст '<текст>'`, после каждого — `И в таблице "<Таблица>" я завершаю редактирование строки`: без него обработчики изменения не срабатывают |
| Проверить значение | `Тогда элемент формы с именем '<Имя>' стал равен '<значение>'`; в таблице — `И в таблице "<Таблица>" поле с именем '<Колонка>' имеет значение '<значение>'` |
| Запомнить значение | `И я запоминаю значение поля с именем '<Имя>' как "<Переменная>"` |
| Записать и открыть заново | `И я нажимаю на кнопку с именем 'ФормаЗаписать'`, `И я сохраняю навигационную ссылку текущего окна в переменную "Ссылка"`, `И я закрываю текущее окно`, `И я перехожу по навигационной ссылке '$Ссылка$'` |
| Записать и закрыть | кнопка `ФормаЗаписатьИЗакрыть`, затем `И я жду закрытия окна '<Заголовок>*' в течение 20 секунд` |
| Дождаться проведения | `И я жду доступности элемента с именем 'ФормаОтменаПроведения' в течение 20 секунд` |

Заголовок новой или изменённой формы кончается звёздочкой: `'... (создание)*'`.

## Грабли

- Ссылочное поле не перебирать построчно и не смотреть скриншотами: сразу шаг из
  таблицы. Значение — по переменной сценария, не первая строка списка.
- Панель функций раздела блокирует клиент, пока не выбрана команда. Раздел открывать
  шагом командного интерфейса; открылась панель — `manage_command_interface`
  с `close_function_panel` один раз.
- Загрузке расширения в рабочую базу мешает открытый клиент тестирования: закрыть
  клиент (`close_test_client` или окно), загрузить, поднять клиент снова и `connect`.
  Менеджер не останавливать — у агента пропадут инструменты `vanessa`.
- «Лимит лицензии» при запуске — сначала найти и закрыть клиент, оставшийся от
  прерванного пакетного прогона; менеджер не трогать.
- Упавший пример оставляет открытое окно и мешает следующему: в `Контексте` закрывать
  все окна, в конце сценария — тоже.
- Сценарий убирает за собой созданное (пометка на удаление с подтверждением диалога)
  или создаёт уникальные данные через переменную.
- Снимок окна Vanessa делает при ошибке шага (параметры — в
  [references/environment.md](references/environment.md)); на зелёном прогоне снимков
  нет, и это норма. Снимки и отчёты — в каталоге логов, в git не идут.
