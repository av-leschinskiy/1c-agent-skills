# Окружение 1С для Vanessa

Значения машины живут в проекте, а не в скилле: скилл обновляется `git pull`, и правка
внутри него конфликтует с обновлением. Скопировать раздел ниже в `AGENTS.md` проекта
и заполнить вместе с человеком. Если раздел «Окружение 1С» уже есть от скилла
`testing-with-yaxunit`, дописать недостающие строки в него.

```markdown
## Окружение 1С

| Что | Значение |
| --- | --- |
| Платформа и путь к `1cv8` / `1cv8c` | `C:\Program Files\1cv8\8.3.xx.xxxx\bin` |
| Рабочая база (строка подключения) | файловая `File="C:\bases\project";` или серверная `Srvr="srv";Ref="base";` |
| Пользователь 1С | `Администратор`; пароль в команды и файлы не вписывать |
| База-менеджер Vanessa | отдельная пустая файловая база, например `C:\vanessa\va-manager` |
| Обработка и расширения | `vanessa-automation-single.epf`, `client_mcp.cfe`, `VAExtension.<версия>.cfe` — пути |
| Профиль клиента тестирования | имя из `VAParams-mcp.json`, на него ссылаются сценарии |
| Адрес MCP | `http://localhost:48100/mcp` |
| Каталог сценариев | `features/` |
| Каталог логов и отчётов (в git не входит) | `logs/vanessa/` |
```

Vanessa и `client_mcp` — из релизов на GitHub (`Pr-Mex/vanessa-automation`,
`onec-client-mcp-devkit`); версии записать рядом с таблицей. `VAExtension.<версия>.cfe` —
отдельный файл в том же релизе Vanessa, что и обработка: версии брать из одного релиза.

Образцы ниже — для Windows и файловой базы. Проверить каждую команду на своей базе и при
расхождении записать рабочий вариант в `AGENTS.md` проекта.

Перед загрузкой расширений и запуском менеджера закрыть клиенты 1С рабочей базы.

## База-менеджер (один раз)

Менеджер тестирования живёт в отдельной пустой базе: в рабочей базе её стартовые окна
не дают открыться обработке. Создать базу, загрузить в неё `client_mcp` и снять с него
безопасный режим и защиту от опасных действий — без этого `client_mcp` не откроет
feature-файл и не сделает снимок:

```bat
"<путь>\1cv8.exe" CREATEINFOBASE File="<база-менеджер>"
"<путь>\1cv8.exe" DESIGNER /F"<база-менеджер>" /DisableStartupDialogs ^
  /LoadCfg "<путь>\client_mcp.cfe" -Extension client_mcp /UpdateDBCfg ^
  /Out "<логи>\client_mcp.log"
ibcmd config extension update --db-path="<база-менеджер>" ^
  --name=client_mcp --safe-mode=no --unsafe-action-protection=no
```

Без `ibcmd` — в Предприятии базы-менеджера: «Все функции → Стандартные → Управление
расширениями конфигурации».

Защита от опасных действий для базы-менеджера — строкой в `conf.cfg` платформы
(`C:\Program Files\1cv8\conf\conf.cfg`), иначе на каждом запуске — предупреждение
безопасности, которое некому подтвердить:

```text
DisableUnsafeActionProtection=.*va-manager.*
```

## Расширение VAExtension (один раз)

`VAExtension` даёт шаги с пометкой «(Расширение)»: выполнение кода на клиенте и сервере
клиента тестирования, ожидание фоновых заданий, «Все функции», состояние объекта,
навигационные ссылки и другие. Без расширения такие шаги падают. Поставить в рабочую
базу и снять безопасный режим — в безопасном режиме не работают шаги с привилегированным
режимом и внешними обработками:

```bat
"<путь>\1cv8.exe" DESIGNER /F"<рабочая база>" /DisableStartupDialogs ^
  /LoadCfg "<путь>\VAExtension.<версия>.cfe" -Extension VAExtension /UpdateDBCfg ^
  /Out "<логи>\VAExtension.log"
ibcmd config extension update --db-path="<рабочая база>" ^
  --name=VAExtension --safe-mode=no
```

Те же команды — для базы-менеджера: без активного `VAExtension` в ней MCP-сервер не
регистрирует инструмент `restart_vanessa`.

Расширение тестовое: в исходники проекта и в хранилище конфигурации не помещать. После
обновления Vanessa загрузить `VAExtension` из того же релиза заново.

Файл `VAParams-mcp.json` в каталоге логов:

```json
{
  "ИспользоватьКомпонентуVanessaExt": true,
  "ИскатьЭлементыФормыПоИмени": true,
  "ТаймаутЗапуска1С": 120,
  "ДиапазонПортовTestclient": "48000-48049",
  "ДанныеКлиентовТестирования": [
    {
      "Имя": "<профиль>",
      "Синоним": "<профиль>",

      "ИмяКомпьютера": "localhost",
      "ДопПараметры": "/N<пользователь> /Lru /VLru"
    }
  ]
}
```

## Запуск для работы агента

Клиент тестирования, затем менеджер с MCP. Оба окна держать открытыми, пока работает
агент; агента запускать **после** менеджера:

```bat
start "" "<путь>\1cv8c.exe" ENTERPRISE /F"<рабочая база>" /N"<пользователь>" ^
  /TESTCLIENT -TPort 48000 /Lru /VLru
start "" "<путь>\1cv8c.exe" ENTERPRISE /F"<база-менеджер>" /TESTMANAGER /Lru /VLru ^
  /DisableStartupDialogs /DisableStartupMessages /Out "<логи>\manager.log" ^
  /Execute "<путь>\vanessa-automation-single.epf" ^
  /C"QuietInstallVanessaExt;runMcp;mcpPort=48100;VAParams=<логи>\VAParams-mcp.json"
```

Клиент закрылся или в базу загрузили расширение — закрыть окно клиента и запустить его
первой командой снова; менеджер не трогать.

Запись MCP для агента — HTTP-сервер `vanessa` с адресом из «Окружения 1С» в MCP-конфиге
харнесса (проектный `.mcp.json` Claude Code, `.cursor/mcp.json`, `.codex/config.toml`
и другие). Новая сессия агента должна видеть инструменты `vanessa`.

## Пакетный прогон

Тот же менеджер, но с параметрами прогона вместо MCP. Каждый прогон — в новый каталог
отчёта:

```bat
"<путь>\1cv8c.exe" ENTERPRISE /F"<база-менеджер>" /TESTMANAGER /Lru /VLru ^
  /DisableStartupDialogs /DisableStartupMessages /Out "<отчёт>\manager.log" ^
  /Execute "<путь>\vanessa-automation-single.epf" ^
  /C"StartFeaturePlayer;QuietInstallVanessaExt;VAParams=<отчёт>\VAParams.json"
```

`VAParams.json` прогона — профиль клиента из `VAParams-mcp.json`, но с портами
`48050-48099`, чтобы не задеть клиента MCP, и ключи:

| Ключ | Значение |
| --- | --- |
| `КаталогФич` | каталог или файл сценариев |
| `ВыполнитьСценарии`, `ЗавершитьРаботуСистемы`, `ЗакрытьTestClientПослеЗапускаСценариев` | `true` |
| `ДелатьОтчетВФорматеjUnit`, `КаталогВыгрузкиJUnit` | `true`, `<отчёт>\junit` |
| `ВыгружатьСтатусВыполненияСценариевВФайл`, `ПутьКФайлуДляВыгрузкиСтатусаВыполненияСценариев` | `true`, `<отчёт>\status.txt` |
| `ДелатьОтчетВФорматеАллюр`, `КаталогВыгрузкиAllure` | `true`, `<отчёт>\allure-results` |
| `ДелатьСкриншотПриВозникновенииОшибки`, `КаталогВыгрузкиСкриншотов` | `true`, `<отчёт>\screenshots` |
| `ИспользоватьВнешнююКомпонентуДляСкриншотов`, `СпособСнятияСкриншотовВнешнейКомпонентой` | `true`, `2` — все окна клиента тестирования (0 — весь экран, 1 — текущее окно) |
| `СписокТеговОтбор`, `СписокТеговИсключение` | теги набора, если отбор не каталогом |

Снимок при ошибке попадает и во вложения шага Allure. HTML-отчёт строит утилита Allure:

```bat
allure generate "<отчёт>\allure-results" -o "<отчёт>\allure-report" --clean
```

Итог прогона — `status.txt` (0 — успех) и JUnit без failures и errors, а не код процесса
1С: он 0 и при упавшем сценарии. Пустой отчёт — не успех.
