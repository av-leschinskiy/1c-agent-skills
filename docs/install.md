# Подключение: инструкция для агента

Человек дал ссылку на этот репозиторий и попросил подключить скиллы и MCP. Ниже — что
сделать. Обновление уже подключённого — [update.md](update.md).

Репозиторий подключается **клоном git** и обновляется **через git**. Механизмы плагинов и
маркетплейсов харнессов (`/plugin`, `codex plugin`, каталоги Cursor), `skill-installer`,
npm-пакеты и копирование файлов не использовать: копия не обновляется, а плагин у каждого
харнесса свой. Клон один, харнесс читает его через ссылки и запись MCP.

Ты работаешь в каком-то харнессе — подключай для него и спроси человека, нужны ли другие
харнессы на этой машине. Формат своего MCP-конфига и каталог своих скиллов ты знаешь
или находишь в документации харнесса; ниже — что туда записать.

## 0. Осмотреться

- Уже подключено? Есть подмодуль с URL этого репозитория в `.gitmodules` проекта, клон
  `~/.agents/vendor/1c-agent-skills` или ссылки на `.../1c-agent-skills/skills/...` в
  каталогах скиллов — тогда это не подключение, а обновление: [update.md](update.md).
- Прочитать `AGENTS.md` (или `CLAUDE.md`) проекта. Если в проекте уже есть свой способ
  работать с 1С — скрипт или CLI для загрузки расширений, файл с адресом базы, правила
  каталогов, — команды ниже выполняются **через него**, а не литералами из этого файла.
  Правила проекта важнее этой инструкции в путях, именах и способе запуска.

## 1. Клон

Спросить человека, где подключать:

- **в проект** — подмодуль `vendor/1c-agent-skills` (или каталог по правилам проекта):
  версия фиксируется коммитом проекта, коллеги получают её вместе с репозиторием;
- **для всех проектов на машине** — клон в `~/.agents/vendor/1c-agent-skills`.

```bash
git submodule add https://github.com/av-leschinskiy/1c-agent-skills.git vendor/1c-agent-skills
# или для всех проектов:
git clone https://github.com/av-leschinskiy/1c-agent-skills.git ~/.agents/vendor/1c-agent-skills
```

Дальше `<клон>` — путь к нему.

## 2. Скиллы

Скиллу `checking-bsl-code` нужен Node.js 22+; Java не обязательна — без неё скрипт
скачает сборку анализатора со встроенной Java.

Для каждого каталога `<клон>/skills/<имя>` создать ссылку `<имя>` в каталоге скиллов
своего харнесса — проектном при подмодуле, пользовательском при клоне для всех проектов:

| Харнесс | В проекте | Для всех проектов |
| --- | --- | --- |
| Codex, Cursor и другие, читающие `.agents/skills` | `.agents/skills` | `~/.agents/skills` |
| Claude Code | `.claude/skills` | `~/.claude/skills` |

- **Подмодуль — относительные ссылки** от каталога скиллов
  (`ln -s ../../vendor/1c-agent-skills/skills/<имя> .agents/skills/<имя>`): абсолютный путь
  твоей машины у коллег не разрешится. Клон для всех проектов — абсолютные.
- Один каталог скиллов бывает ссылкой на другой (например, `.claude/skills → .agents/skills`):
  тогда ссылки создаются один раз, в настоящем каталоге.
- Windows: `New-Item -ItemType Junction -Path <каталог скиллов>\<имя> -Target <клон>\skills\<имя>`
  (без прав администратора; junction требует абсолютный путь — для подмодуля предупредить
  человека, что коллегам на Windows придётся создать ссылки у себя).
- Каталог с тем же именем уже есть — не перезаписывать: показать человеку и спросить.
- Если в проекте есть тесты или проверки состава `.agents/skills` — прогнать их; при отказе
  поправить проверку так, чтобы ссылки в подмодуль считались законными.

## 3. MCP-сервер `onec-objects`

Нужны Node.js 22+, база 1С с HTTP-публикацией (Apache или IIS) и права загрузить в неё
расширение. Если человек не хочет давать агенту запись в базу — этот шаг пропустить.

1. Собрать сервер: `npm --prefix <клон>/mcp/objects ci && npm --prefix <клон>/mcp/objects run build`.
   Каталоги `node_modules/` и `dist/` в git клона не входят.
2. Загрузить в базу расширение из `<клон>/extensions/СервисОбъектов` — способом проекта,
   если он есть (шаг 0), иначе Конфигуратором «Конфигурация → Расширения конфигурации →
   Загрузить из файлов» или командой
   `1cv8 DESIGNER /F"<база>" /N"<пользователь>" /LoadConfigFromFiles "<клон>/extensions/СервисОбъектов" -Extension СервисОбъектов /UpdateDBCfg -Extension СервисОбъектов`.
   Перед этим закрыть сеансы 1С базы — попросить человека, принудительно не завершать.
   XML выгружен в формате 8.3.24; на более новой платформе загрузка выдаёт предупреждение
   о версии формата — это нормально. Опубликовать HTTP-сервисы расширения
   («Администрирование → Публикация на веб-сервере», флажок HTTP-сервисов), если
   публикация их ещё не отдаёт.
3. Проверить сервис: `GET <адрес публикации>/hs/objects/types?q=.&limit=5` с Basic-авторизацией
   пользователя 1С отвечает JSON с `items`. 401 — неверный пользователь, 404 — не
   опубликованы HTTP-сервисы или расширение не загружено.
4. Добавить в MCP-конфиг харнесса stdio-сервер:

   | Поле | Значение |
   | --- | --- |
   | имя | `onec-objects` |
   | команда | `node` |
   | аргументы | `<клон>/mcp/objects/dist/index.js` |
   | окружение | `ONEC_HTTP_URL` — адрес публикации без `/` в конце; `ONEC_USER` — пользователь 1С; `ONEC_PASSWORD` — пароль, если есть |

   - **Пароль** — только в пользовательском конфиге харнесса или в переменной окружения
     системы; в файлы проекта под git не попадает.
   - **Проектный конфиг под git** (при подмодуле) не содержит абсолютных путей твоей
     машины. Если харнесс не понимает относительный путь к `dist/index.js`, запись — в
     пользовательском конфиге.
   - Если проект сам знает адрес базы (скрипт, `stand.json` и т. п.), вместо литералов в
     конфиге — короткий скрипт-обёртка в проекте: вычисляет `ONEC_HTTP_URL` и `ONEC_USER`,
     кладёт в `process.env` и делает `import` файла `<клон>/mcp/objects/dist/index.js`.
5. Проверить в новой сессии: инструмент `find_types` с запросом `.` возвращает типы базы.
   В текущей сессии проверить можно, запустив сервер вручную и отправив ему `tools/list`
   по stdio.

Сервер Vanessa в этот шаг не входит: его запускает менеджер тестирования, запись
описана в скилле `testing-with-vanessa`.

## 4. AGENTS.md проекта

Добавить в `AGENTS.md` проекта короткую запись — **ссылку, а не копию** команд этого файла:
копия устареет при первом обновлении.

```markdown
Внешние инструменты 1С (скиллы, MCP `onec-objects`, расширение `СервисОбъектов`) —
подмодуль `vendor/1c-agent-skills`, файлы в нём не править. Подключение и обновление —
`vendor/1c-agent-skills/docs/`. После клонирования проекта: `git submodule update --init`.
```

Раздел «Окружение 1С» (платформа, база, адрес публикации, пользователь, где логи) скиллы
попросят заполнить при первом использовании; если ты уже узнал эти значения — заполни
сейчас, без паролей.

## 5. Итог человеку

- Что подключено: ревизия клона (`git -C <клон> log -1 --oneline`), ссылки, запись MCP,
  загружено ли расширение.
- **Начать новую сессию агента** — скиллы и MCP харнесс читает при старте.
- Изменения в проекте показать (`git status`) и закоммитить по правилам проекта, если
  человек просит.

## Не делать

- Не править файлы в клоне: всё, что зависит от машины, — в `AGENTS.md` проекта и записи MCP.
- Не класть пароли и токены в `AGENTS.md`, проектные конфиги и коммиты.
- Не ставить эти скиллы плагином или из маркетплейса параллельно с клоном: два источника
  одного скилла расходятся.
