# Порядок доработки 1С с агентом

Для агента: прочитать перед задачей на доработку конфигурации или расширения. Порядок
держат скиллы Superpowers (от спецификации к плану и TDD); этот файл говорит, что в
каждом шаге значит 1С и какой инструмент этого набора где нужен. Как работает каждый
скилл — его `SKILL.md`, здесь не пересказывается. Правила проекта (`AGENTS.md`) важнее
этого файла: например, способ загрузки в базу, каталоги, именование.

## 1. Требование — brainstorming

Задача на доработку начинается со скилла `brainstorming`, даже если она кажется
маленькой: в 1С «маленькое» часто задевает форму, запись и права сразу.

- Что видит пользователь (форма, печать, ответ сервиса) — решает человек; внутреннее
  устройство (модули, реквизиты, способ хранения) — предлагает агент.
- Критерий приёмки — наблюдаемые значения: поле формы, строка ответа, запись в регистре.
  Граница — примерами («9 штук — без скидки, 10 — со скидкой»). Для формы человек может
  дать черновик Gherkin — из него потом выйдет сценарий Vanessa.
- Факты о базе — не по памяти:
  - метаданные, типы, реквизиты, примеры данных — MCP `onec-objects` или выгрузка
    конфигурации проекта;
  - метод или свойство платформы — MCP `bsl-platform`: сигнатура, доступность в
    контексте (клиент, сервер, внешнее соединение), версия платформы.

## 2. План — writing-plans

В плане у каждой части доработки — уровень проверки:

| Что проверяем | Уровень | Скилл |
| --- | --- | --- |
| правило, расчёт, функция без базы | юнит-тест YAxUnit | `testing-with-yaxunit` |
| запись, проведение, движения, права | интеграционный тест YAxUnit с данными в транзакции | `testing-with-yaxunit` |
| то, что пользователь видит и вводит в форме | сценарий Vanessa на критический путь | `testing-with-vanessa` |

Сценарий не дублирует серверные тесты: он проверяет форму, а правило и запись остаются
на YAxUnit. Без своей формы сценарий не нужен.

Если в доработке есть сценарий Vanessa, менеджер тестирования запускается **до** сессии
агента, которая будет его писать: MCP-серверы харнесс подключает при старте сессии.

## 3. Выполнение — TDD

Скилл `test-driven-development` вместе со скиллами тестов из таблицы; крупный план —
`subagent-driven-development` или `executing-plans`.

- Red — падение **на требовании**: ожидали 90, получили 100. Падение на окне, данных,
  загрузке расширения или сценария — сломанный тест, его чинят, это не Red.
- Доработка — в расширении; основная конфигурация не меняется без явного решения человека.
- Загрузка в базу, обновление конфигурации БД и запись данных — изменяющие действия:
  показать человеку команду и получить «ОК» на каждое.
- Перед вызовом незнакомого метода платформы — сверка через `bsl-platform`.

## 4. Перед «готово»

Скилл `verification-before-completion`; в 1С он значит:

1. `checking-bsl-code` по изменённым файлам — без ошибок; замечания показать человеку.
2. Пакетный прогон тестов **без агента**: YAxUnit и Vanessa командой, код возврата 0,
   отчёт свежий и в нём есть выполненные тесты. Пустой отчёт и код 0 процесса 1С —
   не успех.
3. Результат проверен снаружи тем, что видит пользователь: форма, ответ сервиса,
   документ в базе.

## 5. Завершение

Скилл `finishing-a-development-branch`: коммит, merge или MR — по правилам проекта.
Человеку — что сделано, чем проверено (команды и итог) и что осталось за границей
проверки.
